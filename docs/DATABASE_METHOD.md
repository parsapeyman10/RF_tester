# متد ذخیره‌سازی داده — از SD تا دیتابیس

این سند «متد» پیشنهادی و پیاده‌سازی‌شده برای کل مسیر داده است. هیچ‌جای معماری
شما عوض نشده؛ فقط نقص‌هایی که باعث هدررفت فضا، کندی و رکورد تکراری می‌شد بسته شده.

```
ESP32 ──SD(فایل روزانه)──► TCP ──► ESP8266 ──Serial──► Flask ──► SQLite ×2
```

---

## ۱) روی SD: یک فایل در روز، نه یک فایل برای هر رکورد

### مشکل نسخه‌ی قبل
هر رکورد ۲۵ بایتی در یک فایل جدا ذخیره می‌شد (`/data/20260105_42.dat`).
روی FAT هر فایل حداقل **یک کلاستر (۴ تا ۳۲ کیلوبایت)** اشغال می‌کند، یعنی:

| | نسخه‌ی قبل | نسخه‌ی جدید |
|---|---|---|
| فضای اشغالی ۱۰۰۰ رکورد | ۴ تا ۳۲ **مگابایت** | **۲۵ کیلوبایت** |
| تعداد فایل در پوشه | ۱۰۰۰ | ۱ |
| پیمایش پوشه برای آپلود | O(n) در هر دور | O(1) |
| نوشتن روی SD بعد از هر ACK | حذف فایل (عملیات پرهزینه) | فقط ۴ بایت آفست |

### ساختار جدید

```
/data/20260105.dat   ← رکوردهای ۲۵ بایتی پشت سر هم (append)
/data/20260105.pos   ← آفست بایتیِ رکورد بعدی که باید آپلود شود
/last_id.txt         ← آخرین شماره‌ی رکورد (برای ادامه بعد از ریست)
```

- **نوشتن:** `saveToSD()` رکورد را به فایل همان روز append می‌کند.
- **آپلود:** قدیمی‌ترین فایل روزانه برداشته می‌شود، رکورد روی آفست خوانده و
  ارسال می‌شود؛ بعد از دریافت `OK` فقط آفست جلو می‌رود.
- **پاک‌سازی:** وقتی آفست به انتهای فایل رسید و آن روز تمام شده باشد،
  فایل و آفستش حذف می‌شوند. فایلِ امروز هیچ‌وقت حذف نمی‌شود.
- **بازیابی بعد از قطع برق:** چون آفست روی SD است، ارسال دقیقاً از همان رکورد
  ادامه پیدا می‌کند؛ نه رکوردی گم می‌شود و نه دوباره فرستاده می‌شود.

> این فرمت **دقیقاً همان چیزی است که `/upload_dat` در `app.py` می‌خواند**
> (`len(file) % 25 == 0`)؛ پس اگر SD را مستقیم به کامپیوتر بزنید، همان صفحه‌ی
> آپلود بدون هیچ تغییری کل فایل روزانه را می‌بلعد.

## ۲) روی سرور: کلید یکتایی و حذف تکراری‌ها

### منابع رکورد تکراری (هر سه بسته شد)

| منبع | توضیح | راه‌حل |
|---|---|---|
| اکوی سریال ESP8266 | خط `NUM=...` هم به‌صورت خام و هم در `[LINE RECV]` چاپ می‌شد | `DEBUG_ENABLE=false` + پارسر سخت‌گیر |
| گم شدن ACK | ESP32 همان رکورد را دوباره می‌فرستاد | آفست + کلید یکتا در دیتابیس |
| آپلود دوباره‌ی همان پوشه | `/upload_dat` دوباره همه را درج می‌کرد | `master_exists()` و `INSERT OR IGNORE` |

### کلید یکتایی

```
(num_value , تاریخ دستگاه , ساعت دستگاه)
```

- در دیتابیس روزانه به‌صورت ایندکس یکتای واقعی:
  `CREATE UNIQUE INDEX uq_daily_record ON daily_records(num_value, log_date, log_time)`
- در دیتابیس اصلی با `master_exists()` قبل از درج.

### توابع جدید در `app.py`

| تابع | کار |
|---|---|
| `open_daily_db(date)` | اتصال آماده: ساخت جدول + `WAL` + `busy_timeout` + ایندکس‌ها |
| `insert_daily_rows(date, rows)` | درج دسته‌ای با `INSERT OR IGNORE`، خروجی = تعداد رکورد واقعاً جدید |
| `master_exists(num, date, time)` | چک تکراری بودن قبل از درج در دیتابیس اصلی |
| `INDUSTRIAL_LINE_RE` | regex دقیق ۱۳ فیلدی به‌جای `split(',')` |

### پارسر سخت‌گیر سریال

`parse_industrial_line()` حالا فقط خطی را قبول می‌کند که **کامل** باشد و
تاریخش هم **واقعاً معتبر** باشد (مثلاً `2026-02-31` رد می‌شود). خطوط ناقص،
نویزی یا بوت‌لاگ برد دیگر وارد دیتابیس نمی‌شوند — ولی اگر خط سالم در میان
نویز باشد، همان استخراج می‌شود.

### بهینه‌سازی‌های دیگر

- `cleanup_old_databases()` قبلاً **به ازای هر رکورد** کل پوشه را `listdir`
  می‌کرد؛ حالا حداکثر هر ۱۰ دقیقه یک بار.
- `PRAGMA journal_mode=WAL` و `synchronous=NORMAL` روی دیتابیس‌های روزانه
  (نوشتن سریع‌تر و بدون قفل شدن هنگام خواندن همزمان توسط داشبورد).
- پاسخ `/upload_dat` حالا `skipped_duplicates` را هم برمی‌گرداند.

## ۳) اتصال آسان وای‌فای (بدون کامپایل دوباره)

تنظیمات در **NVS** ذخیره می‌شوند (`Preferences`)، و از روی همان پورتال
`SetClock` قابل تغییرند:

- SSID/پسورد شبکه‌ای که برای **گرفتن ساعت از NTP** استفاده می‌شود
- SSID/پسورد **اکسس‌پوینت گیرنده‌ی دیتا** (ESP8266)
- دکمه‌ی **اسکن شبکه‌های اطراف**

یک بار وارد کنید، برای همیشه می‌ماند؛ حتی بعد از فلش دوباره‌ی همین فریمور.

## ۴) تست خودکار

`.github/scripts/test_db_pipeline.py` این‌ها را در CI چک می‌کند:

1. خط استاندارد در هر دو دیتابیس ذخیره می‌شود
2. همان خط سه بار → فقط یک رکورد
3. خطوط ناقص/نویزی/تاریخ نامعتبر اصلاً ذخیره نمی‌شوند
4. خط سالم داخل نویز درست استخراج می‌شود
5. فایل باینری چندرکوردی (۵ رکورد = ۱۲۵ بایت) درست باز می‌شود
6. ایندکس یکتا واقعاً ساخته شده است
