# راه‌اندازی سرور روی کامپیوتر

## ۱) فایل‌هایی که حتماً لازم دارید

```
RF_tester/
├── app.py                ← خود سرور (اجرا می‌شود)
├── requirements.txt      ← لیست پیش‌نیازها
├── run_server.bat        ← اجرای یک‌کلیکی روی ویندوز
├── run_server.sh         ← اجرای یک‌کلیکی روی لینوکس/مک
└── templates/            ← بدون این پوشه خطای TemplateNotFound می‌گیرید
    ├── index.html        ← داشبورد زنده
    ├── history.html      ← آرشیو و خروجی CSV
    ├── plot_display.html ← نمودار
    └── upload.html       ← آپلود دستی فایل‌های .dat
```

فایل‌هایی که **خودکار ساخته می‌شوند** (نیازی نیست داشته باشید):

| فایل | محتوا |
|---|---|
| `instance/master_industrial.db` | آرشیو کامل همه‌ی رکوردها |
| `serial_config.json` | آخرین پورت و باود انتخاب‌شده (بین ری‌استارت‌ها می‌ماند) |
| `YYYY-MM-DD.db` | دیتابیس روزانه (۷ روز نگه داشته می‌شود) |
| `.venv/` | محیط مجازی پایتون |

پوشه‌ی `desktop/` و `android/` برای سرور لازم **نیستند**؛ آن‌ها کلاینت‌اند.

## ۲) اجرا

**ویندوز:** روی `run_server.bat` دوبار کلیک کنید. بار اول محیط مجازی می‌سازد و
پیش‌نیازها را نصب می‌کند (نیاز به اینترنت)، بعد سرور بالا می‌آید.

**لینوکس/مک:**

```bash
./run_server.sh
```

**دستی:**

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt     # ویندوز
.venv/bin/pip install -r requirements.txt         # لینوکس
python app.py
```

خروجی درست:

```
[INIT] templates: C:\...\RF_tester\templates
[INIT] سرور روی http://0.0.0.0:5000 بالا آمد (از گوشی: http://<IP کامپیوتر>:5000)
```

## ۳) آدرس‌ها

| از کجا | آدرس |
|---|---|
| همان کامپیوتر | `http://127.0.0.1:5000` |
| گوشی یا کامپیوتر دیگر | `http://<IP کامپیوتر>:5000` |
| پیدا کردن IP (ویندوز) | `ipconfig` → `IPv4 Address` |

بار اول ویندوز درباره‌ی فایروال می‌پرسد → روی شبکه‌ی **Private** اجازه بدهید،
وگرنه گوشی نمی‌تواند وصل شود.

## ۴) اتصال سریال به ESP8266

۱. کابل USB گیرنده (ESP8266) را به کامپیوتر بزنید.
۲. در داشبورد، پورت COM را انتخاب و **Baud = 115200** بگذارید.
۳. با آمدن هر رکورد در کنسول می‌بینید:

```
[RX] NUM=1178 2026-09-28 16:20:11
```

اگر `[RX_BAD]` دیدید یعنی خط ناقص رسیده (بیشتر وقت‌ها باود اشتباه است).

## ۴.۵) حالت Production (برای روشن ماندن طولانی‌مدت)

```bash
python app.py --prod          # یا روی ویندوز: run_server.bat --prod
```

در این حالت به‌جای سرور توسعه‌ی فلسک از **waitress** استفاده می‌شود:
بدون دیباگر، چندنخی و پایدار. نخ خواندن سریال هم مثل حالت عادی کار می‌کند.

## ۵) مسیرهای سرور

| آدرس | کار |
|---|---|
| `/` | داشبورد زنده |
| `/history` | آرشیو + فیلتر تاریخ + خروجی CSV |
| `/plot_display` | نمودار دما و رطوبت |
| `/upload_dat` | آپلود دستی فایل‌های `.dat` از روی SD |
| `/api/ingest` | ورودی دیتا از اپ گوشی و کلاینت دسکتاپ |
| `/paste` | افزودن دستی با چسباندن متن خام سریال |
| `/import_csv` | ورود همان CSV‌ای که «خروجی اکسل» می‌سازد |
| `/save_data` | دانلود نسخه‌ی پشتیبان کامل دیتابیس (`.db`) |
| `/api/sensor_data` | آخرین ۵۰ رکورد (JSON) |
| `/api/server_time` | ساعت کامپیوتر سرور (جدا از ساعت دستگاه) |
| `/api/recover_unsaved` | بازگرداندن رکوردهایی که در فایل پشتیبان مانده‌اند |

## ۶) اجرای دائمی (اختیاری)

سرور پیش‌فرض، سرور توسعه‌ی فلسک است. برای روشن ماندن طولانی‌مدت:

```bash
.venv\Scripts\waitress-serve --host=0.0.0.0 --port=5000 app:app
```

⚠️ در این حالت نخ خواندن سریال که در `__main__` اجرا می‌شود بالا نمی‌آید؛
اگر داده از سریال می‌گیرید، همان `python app.py` را استفاده کنید.

## ۷) مشکلات رایج

| نشانه | علت و راه‌حل |
|---|---|
| `TemplateNotFound: index.html` | پوشه‌ی `templates/` کنار `app.py` نیست |
| `ModuleNotFoundError: flask` | پیش‌نیازها نصب نشده — `run_server.bat` را اجرا کنید |
| گوشی وصل نمی‌شود | فایروال ویندوز، یا گوشی روی شبکه‌ی دیگری است |
| صفحه‌ی History خالی است | تاریخ انتخابی داده ندارد؛ فیلتر را بردارید |
| `[RX_BAD]` روی کنسول | باود اشتباه یا کابل سریال ضعیف |
