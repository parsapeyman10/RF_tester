# چک‌لیست تست واقعی روی سخت‌افزار

نسخه: فریمور ESP32 **V2.2** — کامیت `d55d3a8`

---

## ۰) قبل از فلش — دو تنظیم

در `esp32_controller_FIXED.ino`، بالای فایل:

```cpp
// اگر مودم/هات‌اسپات دارید (اختیاری؛ خالی هم باشد از ساعت گوشی استفاده می‌شود)
const WifiCred TIME_NETWORKS[] = {
  // { "MyModem", "modem-password" },
};

// نگاشت رله -> BCM . اگر سخت‌افزار شما «رله۱=Open برای هر دو» است، عوضش کنید
const ChannelConfig CHANNELS[] = {
  { "BCM1", 2, 13, 15 },
  { "BCM2", 4, 16, 17 },
};
```

`DEBUG_MODE` را فعلاً روی `1` بگذارید تا لاگ کامل ببینید؛ بعد از تأیید، `0`.

| برد | Board در Arduino IDE | نکته |

## ۲) بوت ESP32 — چه باید ببینید

```
[BOOT] Industrial Controller V2.0
[CFG] data-AP='ESP8266_AP'  time-AP='(none)'
[SD] Card OK.
[SD] Resuming from ID ...
[TIME] No time-network saved; will ask the phone instead.
[PORTAL] SSID 'SetClock' -> http://192.168.1.1/
```

> **مهم:** پورتال در هر بوت باز می‌شود. تا وقتی کلاینتی به `SetClock` وصل
> است، دستگاه **منتظر می‌ماند** و شمارش معکوس متوقف می‌شود؛ تست فقط با
> زدن دکمه‌ی **«▶ تست رله‌ها را شروع کن»** در `http://192.168.1.1` آغاز
> می‌شود. اگر کسی وصل نشود، بعد از ۲ دقیقه خودکار ادامه می‌دهد.

✅ **تست ساعت:** با گوشی به وای‌فای `SetClock` (رمز `12345678`) وصل شوید و
`http://192.168.1.1` را باز کنید. صفحه **خودکار** ساعت گوشی را می‌فرستد:

- بالای صفحه ساعت درست نشان داده شود
- در همان صفحه SSID/رمز مودم و اکسس‌پوینت گیرنده را ذخیره کنید (دکمه‌ی اسکن هم هست)
- دکمه‌ی «شروع کار عادی» را بزنید

> اگر تاریخ فایل‌ها باز هم `20250101` شد، یعنی RTC ست نشده — برگردید به همین مرحله.

## ۳) تست ترتیب رله (مهم‌ترین بخش این نسخه)

روی سریال باید **دقیقاً** این ساختار را ببینید:

```
[CYCLE] ===== Started =====

[TEST] ===== تلاش 1/3 =====
[PHASE OPEN] BCM1:YES  BCM2:YES
[PHASE CLOSE] BCM1:YES  BCM2:YES
[TEST] BCM1 -> Open:YES Close:YES (OK)
[TEST] BCM2 -> Open:YES Close:YES (OK)
[TEST] هر دو دستگاه OK در تلاش 1 — تکرار لازم نیست

[CYCLE] #1178  BCM1=OK  BCM2=OK  T=24.10 H=41.20 @ 2026-09-28 16:20:11
```

بررسی کنید:

- [ ] در هر فاز، رله **دقیقاً در طول پنجره‌ی مانیتورینگ** فعال باشد (با مولتی‌متر)
- [ ] فیدبک هر دو BCM در همان فاز خوانده شود (نه یکی بعد دیگری)
- [ ] وقتی هر دو OK شدند، **تلاش دوم اصلاً اجرا نشود**
- [ ] اگر یک دستگاه ناقص ماند، فقط همان فاز تکرار شود (`[PHASE ...] رد شد` را ببینید)
- [ ] نگاشت پین‌ها درست باشد:

```cpp
const uint8_t RELAY_PINS[2]  = { 2, 4 };       // رله۱ = OPEN ، رله۲ = CLOSE
const uint8_t FEEDBACK_PINS[2][2] = {
  { 13, 16 },   // OPEN : BCM1=13 , BCM2=16
  { 15, 17 },   // CLOSE: BCM1=15 , BCM2=17
};
```

## ۴) تست ذخیره‌سازی (کارت SD یا حافظه‌ی داخلی)

دستگاه دو سطح ذخیره‌سازی دارد:

| حالت | چه می‌شود |
|---|---|
| کارت SD هست | همه‌چیز روی کارت نوشته می‌شود |
| کارت نیست | همان ساختار روی **حافظه‌ی داخلی ESP32** نوشته می‌شود (~۴۰٬۰۰۰ رکورد) |
| کارت وسط کار درآید | خودکار به حافظه‌ی داخلی سوییچ می‌کند |
| کارت بعداً جا زده شود | ظرف ۶۰ ثانیه تشخیص، فایل‌ها منتقل و روی کارت ادامه |

در لاگ بوت:

```
[STORE] کارت SD آماده است (7648 مگابایت)
        یا
[STORE] کارت SD پیدا نشد -> استفاده از حافظه‌ی داخلی
[STORE] حافظه‌ی داخلی آماده است (1012 کیلوبایت آزاد)
```

و در خط سلامت: `حافظه=SD(7600000k آزاد)` یا `حافظه=حافظه داخلی(1012k آزاد)`

### تست قدیمی کارت

```
[SD] Appended #1178 -> /data/20260928.dat
```

- [ ] فقط **یک فایل در روز** ساخته شود (نه یک فایل برای هر رکورد)
- [ ] اندازه‌ی فایل هر سیکل ۲۵ بایت زیاد شود
- [ ] یک فایل `20260928.pos` هم کنارش باشد

## ۶) تست حالت دیتا (گوشی و کامپیوتر باید یکی باشند)

از پورتال «حالت نمایش دیتا» را انتخاب کنید؛ ESP32 اکسس‌پوینت `RF_TESTER`
(رمز `12345678`, آی‌پی `192.168.1.1`) را بالا می‌آورد.

**با کامپیوتر:**

```bash
python dist/RFTester.pyz --web --app-server http://127.0.0.1:5000
# IP=192.168.1.1  Port=80  →  sync10  →  «ارسال به app.py»
```

**با گوشی:** همان APK، همان IP/پورت، همان دکمه‌ی «ارسال به app.py»
(آدرس سرور = آی‌پی کامپیوتر در شبکه، مثل `http://192.168.1.100:5000`).

- [ ] خروجی هر دو **عین هم** باشد (هر دو خط‌های `NUM=...`)
- [ ] جواب سرور: `saved=N, duplicates=0`
- [ ] اگر همان دیتا را با آن یکی دستگاه هم بفرستید: `saved=0, duplicates=N`

تست سریع بدون سخت‌افزار (برای اطمینان از سمت سرور):

```bash
curl -X POST http://127.0.0.1:5000/api/ingest -H "Content-Type: application/json" \
  -d '{"lines":["NUM=1,NBCM1=OK,NBCM2=OK,NBCM3=NOK,NBCM4=NOK,Temp=20.00,Humidity=40.00,Date=2026-09-28,Time=10:00:00"]}'
```

## ۷) تست پایداری (بگذارید بماند)

هر ۳۰ ثانیه:

```
[HEALTH] heap=183204 min=170112 | hb R:12 D:48 S:12 N:9412 | up=1440s
```

- [ ] `heap` در طول چند ساعت **کاهش پیوسته** نداشته باشد (نشت حافظه)
- [ ] `hb N:` مدام زیاد شود
- [ ] `up=` صفر نشود (یعنی ریست نخورده)
- [ ] دستگاه را ۲۴ ساعت روشن بگذارید و آخرش `up=` را ببینید

## ۷.۵) پاک‌سازی کارت حافظه

سه راه، هر سه با تأیید صریح:

| راه | چطور |
|---|---|
| **ترمینال Arduino** | در کادر بالای Serial Monitor بنویسید `FORMAT SD` و Enter |
| **پورتال SetClock** | کارت «کارت حافظه» → دکمه‌ی «پاک‌سازی کارت حافظه» |
| **حالت دیتا (TCP)** | دستور `format CONFIRM` |

خروجی:

```
[SD] شروع پاک‌سازی کارت حافظه ...
[SD] پاک‌سازی تمام شد: 14 فایل (312 کیلوبایت) حذف شد، شماره‌ی رکورد از ۱ شروع می‌شود
```

فرمان `STATUS` هم روی سریال وضعیت لحظه‌ای را می‌دهد.

> این پاک‌سازی، همه‌ی فایل‌های `/data`، آفست‌های آپلود و شمارنده‌ی رکورد را
> حذف می‌کند. فرمت واقعی FAT در کتابخانه‌ی SD هسته‌ی ESP32 وجود ندارد؛ اگر
> کارت خراب شده باشد، روی کامپیوتر با FAT32 فرمتش کنید.

## ۷.۶) اگر خطای `4WAY_HANDSHAKE_TIMEOUT` گرفتید

این یعنی مبادله‌ی چهارمرحله‌ای رمز کامل نشد. به ترتیب:

| # | بررسی | کار |
|---|---|---|
| ۱ | فاصله‌ی بردها | اگر کنار هم روی میزند، **حداقل یک متر** جدا کنید |
| ۲ | توان فرستنده | پیش‌فرض کم شده (`STA_TX_POWER` و `AP_TX_POWER = 14`)؛ دستکاری نکنید |
| ۳ | یکی بودن رمز | `DATA_AP_PASS` در ESP32 و `PASSWORD` در ESP8266 |
| ۴ | نوع رمزنگاری | با `LOG_LEVEL 2` مقدار `enc` را ببینید؛ باید `3` (WPA2) باشد |
| ۵ | تغذیه | ESP8266 با USB ضعیف، موقع ارسال افت ولتاژ می‌دهد |
| ۶ | تست قطعی | در ESP8266 مقدار `AP_OPEN_TEST` را `true` و در ESP32 مقدار `DATA_AP_PASS` را `""` کنید |

اگر با اکسس‌پوینت **بدون رمز** وصل شد → مشکل احراز هویت است.
اگر باز هم وصل نشد → مشکل رادیویی یا تغذیه است، نه نرم‌افزار.

## ۸) اگر چیزی خراب بود

لاگ سریال ESP32 + خروجی کنسول `app.py` را بفرستید؛ با همین دو تا دقیقاً
معلوم می‌شود مشکل از فیدبک، از آپلود، یا از دیتابیس است.
