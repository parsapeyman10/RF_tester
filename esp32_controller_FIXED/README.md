# 📘 راهنمای کامل خط‌به‌خط — `esp32_controller_FIXED.ino`

**پروژه:** کنترلر صنعتی ESP32 نسخه V1.7.1 (بخش فرستنده / Master)
**مهندس:** Peyman Parsa

---

## این فایل کلاً چی‌کار می‌کنه؟ (خلاصه ۳۰ ثانیه‌ای)

این کد روی یک **ESP32** اجرا می‌شود و مغز سیستم تستر صنعتی است:

1. **هر ۲ دقیقه یک سیکل تست** اجرا می‌کند: با دو رله، درب‌ها (یا کلیدها/کنتاکتورها) را باز و بسته می‌کند.
2. با ۴ ورودی دیجیتال **نتیجه حرکت را مانیتور می‌کند** (آیا کانال ۱ باز شد؟ بسته شد؟ کانال ۲ چطور؟).
3. اگر درب **گیر کند**، ۵ ضربه‌ی سریع (Hammering) به رله می‌زند تا باز شود؛ اگر درست نشد تا ۳ بار کل سیکل را تکرار می‌کند.
4. **دمای و رطوبت** را با سنسور SHT31 می‌خواند (با فیلتر نویز و میانگین‌گیری).
5. **ساعت و تاریخ** را از آی‌سی RTC مدل PCF8563 می‌گیرد.
6. نتیجه را به صورت فایل باینری روی **کارت SD** ذخیره می‌کند (Store & Forward: اگر اینترنت/شبکه قطع بود، داده گم نمی‌شود).
7. به شبکه‌ی **ESP8266_AP** (برد دوم) وصل می‌شود و داده‌ها را آپلود می‌کند؛ بعد از دریافت تأیید (ACK)، فایل را از SD پاک می‌کند.
8. اگر نتوانست به شبکه وصل شود، خودش **هات‌اسپات** می‌سازد تا با موبایل/لپ‌تاپ وصل شوی و ساعت را تنظیم کنی یا داده‌های ذخیره‌شده را ببینی.

## 🗺️ معماری کلی — ۴ تسک هم‌زمان (FreeRTOS)

این سیستم multitasking است؛ یعنی ۴ برنامه‌ی مجزا هم‌زمان روی ESP32 اجرا می‌شوند. **همه روی Core 1** سنجاق شده‌اند تا Core 0 آزاد بماند برای کارهای داخلی WiFi (این همان «جداسازی هسته»ای است که در هدر فایل ذکر شده و از تداخل WiFi با SPI و واچداگ جلوگیری می‌کند).

| تسک | اولویت | کاری که می‌کند |
|---|---|---|
| `TaskDigitalRead` (خط 599) | 6 (بالاترین) | وقتی اجازه داده شد، ۴ ورودی را اسکن می‌کند و پالس‌های واقعی را از نویز تشخیص می‌دهد |
| `TaskRelayControl` (خط 465) | 5 | مغز سیستم؛ هر ۲ دقیقه سیکل باز/بسته + منطق چکش‌کاری + ثبت نتیجه |
| `TaskReadSHT` (خط 672) | 3 | خواندن دما/رطوبت و ساعت، با فیلتر هوشمند |
| `TaskInternalWiFiConnection` (خط 826) | 2 | ذخیره روی SD + آپلود به سرور / حالت هات‌اسپات دیباگ |

**ابزارهای هماهنگی بین تسک‌ها:**

| ابزار | نام متغیر | نقش |
|---|---|---|
| Queue (صف) | `xDataQueue` | صف داده‌های آماده برای ذخیره/ارسال (ظرفیت ۲۰ رکورد) |
| Mutex (قفل) | `xSDMutex` | فقط یک تسک در هر لحظه به کارت SD دست بزند |
| Mutex | `xGlobalStateMutex` | قفل روی متغیرهای مشترک تا دو تسک هم‌زمان نویزشان نکنند |
| Event Group (پرچم‌ها) | `xDoorEvents` | ۸ بیت خبر برای هماهنگی («شروع مانیتورینگ»، «وای‌فای آزاد است» و...) |

## بخش ۴ — کلاس RTC (ساعت واقعی PCF8563) (خطوط ۳۲ تا ۱۱۹)

PCF8563 یک آی‌سی ساعت/تقویم است که با باتری حتی بعد از خاموشی، زمان را نگه می‌دارد. با I2C کار می‌کند.

| خط | کد | توضیح |
|---|---|---|
| 33 | `#define RTC_ADDRESS 0x51` | آدرس I2C ثابت این آی‌سی (هگز ۵۱) |
| 34 | `class Rtc_Pcf8563 {` | تعریف کلاس — همه‌ی توابع کار با RTC در یک جا |
| 36 | `Rtc_Pcf8563() {}` | سازنده‌ی خالی (موقع ساخت شیء کاری نمی‌کند) |
| 37–44 | `initClock()` | رجیستر کنترل (آدرس 0x00) را با مقدار 0x00 می‌نویسد تا RTC فعال شود. اگر `endTransmission` غیرصفر برگرداند یعنی آی‌سی پاسخ نداده → پیام خطا |
| 45–52 | `setTime(hour, minute, second)` | از رجیستر 0x02 شروع می‌کند و ۳ بایت می‌نویسد: ثانیه، دقیقه، ساعت. چون PCF8563 اعداد را به فرمت **BCD** می‌خواهد، هر عدد با `decToBcd` تبدیل می‌شود |
| 53–61 | `setDate(day, weekday, month, century, year)` | از رجیستر 0x05 شروع به نوشتن تاریخ می‌کند. `century << 7` بیت هفتم رجیستر ماه را برای قرن (۱۹xx/۲۰xx) تنظیم می‌کند |
| 62–74 | `formatTime()` | اشاره‌گر رجیستر را روی 0x02 می‌برد، ۳ بایت می‌خواند، ماسک می‌زند (`0x7F` برای ثانیه/دقیقه، `0x3F` برای ساعت — بیت‌های اضافی فلگ هستند و باید حذف شوند)، BCD را به عدد عادی تبدیل می‌کند و رشته‌ای مثل `"14:30:05"` می‌سازد و برمی‌گرداند |

| 91–108 | `getSecond()` … `getYear()` | شش تابع getter که آخرین مقدار خوانده‌شده را برمی‌گردانند (بدون رفتن دوباره به باس؛ یعنی اول باید `formatTime/formatDate` صدا زده شود) |
| 110–119 | بخش `private` | |
| 111–113 | `decToBcd(val)` | تبدیل عدد دهدهی به BCD: رقم دهگان می‌رود نیم‌بایت بالا (`<< 4`)، رقم یکان نیم‌بایت پایین. مثلاً 25 → 0x25 |
| 114–116 | `bcdToDec(val)` | برعکس: بالا را می‌گیرد ×۱۰ + پایین. 0x25 → 25 |
| 117 | `char strTime[9], strDate[11];` | بافرهای رشته برای خروجی (۸ کاراکتر + `\0`) |

## بخش ۵ — ساختار داده‌ی `WifiData` (خطوط ۱۲۱ تا ۱۳۱)

```cpp
#pragma pack(1)               // خط 122
struct WifiData {             // خط 123
  int NUM;                    // شماره‌ی سریال رکورد (۴ بایت)
  float Temp;                 // دما (۴ بایت)
  float Hum;                  // رطوبت (۴ بایت)
  bool NBCM1..NBCM4;          // وضعیت سلامت ۴ کانال: true=OK (۴ بایت)
  int Year;                   // سال (۴ بایت)
  uint8_t Month..Second;      // ماه/روز/ساعت/دقیقه/ثانیه (۵ بایت)
};
#pragma pack()                // خط 131
```

- **`#pragma pack(1)`** به کامپایلر می‌گوید بین فیلدها **هیچ فضای خالی (padding) نگذار** — چون این ساختار بایت‌به‌بایت روی SD نوشته و خوانده می‌شود و بین دو برد رد و بدل می‌شود؛ اگر ترازبندی متفاوت باشد داده‌ها خراب خوانده می‌شوند. اندازه‌ی دقیق ساختار: **۲۵ بایت**.
- `NBCM3` و `NBCM4` فعلاً همیشه `false` ثبت می‌شوند (رزرو برای آینده).

| 866–۹۳۵ | **ب) آپلود با الگوی Store & Forward:** اگر WiFi وصل است → زیر قفل SD پوشه‌ی `/data` را باز می‌کند و **اولین** فایل `.dat` را برمی‌دارد → ۲۵ بایت باینری می‌خواند → به سرور `192.168.4.1:80` (برد ESP8266) وصل می‌شود → رکورد را به رشته‌ی متنی `NUM=…,NBCM1=OK/NOK,…,Temp=…,Humidity=…,Date=…,Time=…` تبدیل و با `println` می‌فرستد (**نکته‌ی کامنت خط ۸۷۸–۸۸۰: این فرمت باید دقیقاً با `sscanf` طرف ESP8266 یکی باشد وگرنه پاسخ OK نمی‌آید و فایل هرگز پاک نمی‌شود**) → تا ۳ ثانیه منتظر ACK (خطی که «OK» داشته باشد) می‌ماند — توجه خط ۹۰۲: به‌جای `delay` از `vTaskDelay(5ms)` استفاده شده تا واچداگ ریسِت نکند → **فقط اگر ACK آمد، فایل از SD پاک می‌شود** (`SD.remove` در خط ۹۰۷)! اگر شبکه قطع بود یا سرور جواب نداد، فایل می‌ماند و دور بعد دوباره سعی می‌شود → هیچ دیتایی گم نمی‌شود |
| 928–۹۳۳ | قفل SD آزاد، case تمام |

### CASE 1 — `MODE_HOTSPOT_VIEW` (خطوط ۹۴۴–۱۰۲۵) — نمایش داده روی هات‌اسپات

در این مد تسک رله عملاً بی‌کار است، پس به `WIFI_PERMIT` هم نیازی نیست.

| خط(ها) | کار |
|---|---|
| 948–۹۵۲ | بار اول: سرور دیباگ روی پورت ۸۰ روشن می‌شود |
| 954–۹۶۲ | اگر کلاینت وصل شد و دستوری داد، خط دستور خوانده و تمیز می‌شود |
| **دستور `sync` (۹۴۸–۹۸۱)** | «آخرین دیتا»: زیر قفل SD کل فایل‌های `.dat` را می‌گردد، از اسم (`تاریخ_ID.dat`) بزرگ‌ترین ID را پیدا می‌کند (خط ۹۶۵)، آن فایل را با `sendDataFile` به‌صورت JSON می‌فرستد (خط ۹۷۵)؛ اگر هیچ فایلی نبود `NO_DATA` می‌فرستد |
| **دستور `sync10` (۹۸۴–۱۰۲۱)** | «۱۰ تای آخر»: یک **بافر چرخشی** (Ring Buffer) ۱۰تایی (`last10[count % 10]` — خط ۹۸۹) اسم فایل‌ها را نگه می‌دارد → بعد از شمردن کل فایل‌ها، از نقطه‌ی درست شروع می‌کند و ۱۰ رکورد آخر را داخل `[ ... ]` به شکل آرایه‌ی JSON با `,` جدا شده می‌فرستد |
| 1024–۱۰۲۵ | قطع اتصال کاربر و لاگ |

### پایان حلقه (خط ۱۰۳۰)
`vTaskDelay(100ms)` — استراحت کوتاه تا CPU خفه نشود و تسک‌های دیگر نوبت بگیرند.

## بخش ۲۱ — `saveToSD()` (خطوط ۱۰۳۴ تا ۱۰۴۵)

اسم فایل را می‌سازد: `/data/YYYYMMDD_ID.dat` (مثلاً `/data/20260615_42.dat`) → برای نوشتن باز می‌کند → **دقیقاً ۲۵ بایت** ساختار را باینری می‌نویسد → می‌بندد و لاگ. اگر باز نشد خطای بحرانی. (همین `f.write` باینری است که طرف خواننده با `f.read` همان ۲۵ بایت را برمی‌دارد.)

## بخش ۲۲ — `loop()` (خطوط ۱۰۴۷ تا ۱۰۴۹)

```cpp
void loop() {
  vTaskDelete(NULL);
}
```

چون همه‌ی کارها در تسک‌های FreeRTOS است، `loop` آردوینو در همان اجرای اول **خودش را حذف می‌کند** (`NULL` یعنی «تسک فعلی») تا CPU هدر نرود.

# 🔄 خلاصه‌ی سفر یک رکورد داده (Data Flow)

```
رله‌ها کار می‌کنند (TaskRelayControl)
   ├─► ورودی‌ها پایش می‌شوند (TaskDigitalRead) ──► raw_N1_Open... تخته‌سیاه
   ├─► دما/رطوبت/ساعت خوانده می‌شود (TaskReadSHT) ──► globalSystemState
   └─► رکورد نهایی ──(xDataQueue)──► تسک WiFi
                                        │
                                        ├─► ذخیره روی SD (saveToSD)
                                        └─► اگر وای‌فای وصل: آپلود به ESP8266
                                              └─► ACK آمد؟ ── بله: پاک از SD ── نه: بمان برای دور بعد
```

# 📖 واژه‌نامه‌ی سریع

| اصطلاح | معنی ساده |
|---|---|
| **FreeRTOS / Task** | سیستم‌عامل بلادرنگ؛ هر Task یک برنامه‌ی موازی با اولویت و استک خودش |
| **Mutex (سماfor قفل)** | قفل درِ حمّام! فقط یک نفر داخل؛ بقیه صبر می‌کنند — برای SD و متغیر مشترک |
| **Event Group Bits** | تابلوی اعلانات ۸ خانه‌ای؛ هر تسک بیت‌های مربوط به خود را تماشا می‌کند |
| **Queue** | صف نامه؛ Relay نامه می‌اندازد، WiFi برمی‌دارد |
| **volatile** | «همیشه تازه بخوان» — برای متغیرهایی که بین تسک‌ها رد و بدل می‌شوند |
| **BCD** | روش ذخیره‌ی اعداد در آی‌سی RTC: هر رقم در یک نیم‌بایت |
| **`#pragma pack(1)`** | بدون فاصله‌ی مخفی بین فیلدهای ساختار — ضروری برای ذخیره/انتقال باینری |
| **`pdMS_TO_TICKS(ms)`** | تبدیل میلی‌ثانیه به واحد زمانی (Tick) رایج در FreeRTOS |
| **Store & Forward** | اول ذخیره کن، بعد موفق شدی بفرست و پاک کن — داده هرگز گم نمی‌شود |
| **Hammering** | ۵ پالس کوتاه پیاپی به رله برای رهایی دربِ گیرکرده |
| **ACK** | پیغام «Received OK» از سرور؛ سندِ حذف فایل از SD |
