# RF Tester — اپ اندروید نود بدنه

اپلیکیشن اندروید برای **دو محصول نود بدنه** با تأکید روی:

- رابط زیبا و روان (Jetpack Compose + Material 3، فارسی/RTL)
- **دیتابیس سبک و کامل** (Room/SQLite): زمان، تاریخ، دما، رطوبت + وضعیت کانال‌ها
- **Store & Forward واقعی**: بدون وای‌فای ذخیره → به‌محض اتصال، ارسال به سرور
- حالت‌های گرافیکی و تحلیل‌های مفید بدون شلوغی

---

##۱) اجرا در Android Studio

1. Android Studio → **Open** → پوشه `android/` همین مخزن
2. صبر کنید تا Gradle Sync تمام شود (Gradle 8.9 + AGP 8.7.3)
3. دستگاه/امولاتور را وصل کنید → **Run ▶**

> **نکته Wrapper:** به دلیل محدودیت شبکه داخل محیط ساخت، فایل `gradle-wrapper.jar`
> اینجا قرار نگرفت. یکی از این دو کار را یک‌بار انجام دهید:
> - Android Studio معمولاً خودش پیشنهاد Sync/دانلود می‌دهد؛ یا
> - اگر Gradle روی سیستم نصب است: `cd android && gradle wrapper --gradle-version 8.9`
>
> سپس:
> ```bash
> cd android
> ./gradlew :app:assembleDebug
> ```

##۲) تنظیمات اتصال به سرور

از **تنظیمات** در اپ، آدرس سرور Flask را وارد کنید؛ مثلاً:

```
http://192.168.1.10:5000
```

(IP سیستمی که `app.py` روی آن اجراست؛ لپ‌تاپ و گوشی باید یک شبکه باشند.)

سرور Flask این پروژه از نسخه فعلی این شاخه این‌ها را دارد:

| Endpoint | متد | نقش |
|---|---|---|
| `/api/ingest` | POST | دریافت بچ خوانش‌های آفلاین اپ |
| `/api/master_data` | GET | دریافت آرشیو (پارامتر جدید `limit`) |
| `/api/sensor_data` | GET | آخرین‌ها |
| `/api/app_health` | GET | سلامت سرور برای اپ |

##۳) رفتار آفلاین (مهم)

```
بدون وای‌فای ──► ذخیره در Room (sync_state=1)
                      │
        برقراری اتصال │  (Listener شبکه + WorkManager هر ۱۵ دقیقه)
                      ▼
              POST /api/ingest ──► سرور (با تشخیص تکرار)
                      │
                      ▼
              sync_state=0  (ارسال‌شده)
```

- بنر بالای داشبورد همیشه وضعیت را نشان می‌دهد.
- تپ روی بنر = تلاش فوری ارسال.
- دکمهٔ «بروزرسانی» در نوار بالا = همگام‌سازی دستی (ارسال + دریافت).

##۴) ساختار دیتابیس محلی (سبک + کامل)

جدول `readings`:

| ستون | تایپ | چرا |
|---|---|---|
| `id` | TEXT PK | یکتا (UUID یا کلید سرور) |
| `node_id` | INTEGER | ۱ یا ۲ (دو محصول) |
| `temp` / `humidity` | **REAL** | محاسبات دقیق، حجم کم (نه رشته!) |
| `ts` | **INTEGER (epoch ms)** | سورت/بازه/ایندکس بدون ابهام فرمت |
| `date_str` | TEXT | پارتیشن روزانه و نمایش |
| `time_str` | TEXT | نمایش ساعت سنسور |
| `num_value` | INTEGER | شماره سیکل دستگاه |
| `nbcm_mask` | INTEGER | بیت‌فیلد N1..N4 به‌جای ۴ متن |
| `sync_state` | INTEGER | صف Store & Forward |
| `dedupe_key` | TEXT | جلوگیری از تکرار هنگام دوطرفه‌سازی |

ایندکس‌ها: `(node_id, ts)`، `(ts)`، `(sync_state)`، `(date_str)`، `(node_id, date_str, ts)`

همهٔ خوانش‌ها به **وقت تهران** برچسب می‌خورند.

##۵) صفحات و تحلیل‌ها

| صفحه | محتوا |
|---|---|
| **داشبورد** | دو کارت نود + اسپارک‌لاین + آمار ۲۴ساعته + شاخص راحتی + صف ارسال |
| **نمودارها** | سه حالت: **خطی / مساحتی / میله‌ای**؛ متریک دما/رطوبت؛ فیلتر هر نود؛ بازه ۱س تا همه؛ الگوی ساعتی؛ میانگین روزانه؛ تپ/درگ روی نمودار (Tooltip) |
| **تحلیل** | Min/Max/Avg/Median/σ، روند، **مقایسه دو نود**، **همبستگی دما↔رطوبت**، **ناهنجاری (>2.5σ)**، درصد فعال کانال‌ها |
| **تاریخچه** | جست‌وجوی سریع، فیلتر تاریخ و نود، لیست روان |
| **تنظیمات** | آدرس سرور، نام دو نود، مدت نگهداری، پاک‌سازی، حالت تیره |

##۶) نکته‌های سخت‌افزاری

تغییرات کد ESP32/ESP8266 که گفتید در ادامه می‌گویید — این اپ از همان فرمت پکت
`NUM=...,Temp=...,Humidity=...,Date=...,Time=...` استفاده می‌کند و با تغییرات شما
سازگار خواهد ماند (فقط کافی است فرمت کلیدها حفظ شود).
